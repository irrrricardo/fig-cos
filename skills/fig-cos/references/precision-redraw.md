# 模糊输入下的结构精绘

本分支仅在用户明确要求结构精绘、重画或探索替代修复方法时使用。2026-10-29 用户已选定 [Previous local tracing](local-tracing.md) 为参考图片复现默认；输入模糊或“更清晰/精致”不自动触发本分支。目标仍是保留原图组件的形象与结构。找不到高清源文件不阻止探索，但不授权用同类通用图标替换具体形态。方法选择、约束与研究边界见 [保形修复](reference-fidelity.md)。

## 区分三种准确性

- 表达准确性：类别、可见部件、方向、连接、数量、标签和布局。
- 绘制精度：轮廓连续、交叠清晰、线宽统一、材质/光影一致，在目标尺寸与放大后均可读。
- 科学身份准确性：确切分子结构、细胞亚型、原子连接或未观测部件，必须有文献、数据或用户确认。清晰渲染不能替代证据。

模糊图仍可支持前两者的最佳努力重绘，但不能保证在任何条件下恢复第三者。不要把补画的细节说成原图中真实存在的细节。仅保留原图能支持的确定关系；确实缺少科学身份时标注“结构示意”，必要时只问阻塞问题，其余区域继续完成。

## 执行方法

1. 按物体/关系拆分，记录能看清的轮廓、主要部件、前后遮挡、状态与位置；区分确定、推断和不明。
2. 先在原图上定位轮廓、部件交界与关键连接，再用几何/Bézier 沿这些证据重建。垃圾桶保留原来的桶盖透视、桶沿衔接、桶身各面的比例和可见轮子；不按“垃圾桶通常有什么”补画。蛋白保留参考中螺旋的走向、连续带状外观、连接环与前后遮挡，不用串珠、堆叠圆片或另一种折叠代替。细胞保留原有群体轮廓、可见分界与大小关系。
3. 按任务选择直接精绘、准确匹配的矢量素材或参考约束下的 AI 插画。后者遵循 [ai-assets.md](ai-assets.md)，先核对结构再转矢量，不默认让生成模型填补未知机制。新绘制器只需交付 SVG，接口不依赖特定图库或模型。
4. 用克制的明暗、边缘高光、厚度和遮挡增加层次；不能以任意多的装饰性细胞器、分子连接或拟真纹理代替精确表达。用户认可的文字和框保持不动。
5. 固定同一画布位置，在原图同尺度与局部 4–8 倍放大下比较，并将新矢量渲染后降采样回原图检查。只有锯齿变圆、原结构变了，不算精确复现。结构未通过时不以“示意”标签掩盖复现失败；保留原来的较忠实结果，把新候选标为实验。用户接受重新设计时才采用新的形态。

2×/4× Lanczos、锐化和更密的描摹路径都不会增加原始信息。它们可以改善采样，不能单独满足“高清精绘”。需报告原始像素而非放大后的输入像素：

```powershell
python SKILL/scripts/asset_quality.py --source crop.png --original-size 132 175 --placed-width 132 --canvas-width 1008 --preview-width 3200 --output quality.json
```

这个报告提供原始信息与目标显示尺寸的关系，不自动判定图形正确或好看。SVG 仅是容器，路径数量不是清晰度评分。

## 已有示例绘制器

`refined_components.py` 提供可运行示例，场景中仍用 `kind=parametric`：

| generator | 部件 | 使用边界 |
| --- | --- | --- |
| wheeled-bin | 桶盖、桶身前侧面、轮子、回收标志、高光 | 蓝色带轮垃圾桶的结构示意；可按本任务形状修改 SVG |
| metal-bin | 锥形桶身、凹槽、卷边、椭圆桶盖 | 金属垃圾桶示意 |
| ribbon-protein | 平滑连接线、螺旋带、片层箭头和前后面 | 通用蛋白丝带示意，不代表截图对应的确切拓扑或 PDB 身份 |
| cell-aggregate | 连续细胞边界、胞质、核、明暗与分组 | 规则细胞簇示意；palette 为 orange/blue，positions 为 x,y,r 列表。数量/位置按证据约束 |

这些是从头设计的通用绘制示例，不是“任意物体高清恢复模型”。2026-10-29 的垃圾桶和蛋白示例在有参考图的复现中被用户否决：形态发生改变，螺旋呈串珠感。不能再把它们直接当作模糊原图的升级版。保留接口供设计任务使用；复现需基于具体参考重写几何并独立验收。对其他对象同样不以同类模板替代原有形态。

## 原生渐变与编辑效率

支持 objectBoundingBox 的水平/垂直线性填色渐变及正交变换，显式 hex 色标、色标 alpha 与整体透明度可保留为 PowerPoint 原生渐变。SVG 中的 defs/linearGradient/stop 需使用本地 fill 引用，`place_component` 会为多实例重新命名引用。

渐变文字/描边、任意方向或范围、userSpaceOnUse、继承/gradientTransform、径向渐变尚未支持；会报错，不能说已经无损转换。图标规范化器仍只负责平面路径，有渐变的自绘组件直接装配，不送入只处理扁平图标的 normalize。

正确的几何和原生渐变可减少碎路径，并按部件独立编辑。最终仍要看 SVG 与实际 PowerPoint 预览，不能用 XML 检查代替视觉验收。
